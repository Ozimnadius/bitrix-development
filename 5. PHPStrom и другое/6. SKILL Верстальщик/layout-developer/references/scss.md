# SCSS-структура

Правила стилей: куда положить файл, как его подключить, что взять готовым, как писать вложенность, адаптив и hover.

Имена в угловых скобках — слоты `PROJECT.md`. В код они не попадают: сначала подставляется значение из контракта, и если слот пуст — сначала бутстрап.

## Куда положить стили

Прежде чем создавать файл, определить, к чему стиль относится:

| Что стилизуем | Куда |
|---|---|
| BEM-блок, переиспользуемый на разных страницах | файл в `<blocks-dir>` + подключение в `<blocks-index>` |
| стили, нужные только одной странице | `<pages-dir>`, подключается на самой странице |
| разметку конкретного шаблона компонента | `style.scss` этого шаблона |

Page-only стили не добавляются ни в `<scss-entry>`, ни в `<blocks-index>`. Стили шаблона компонента не выносятся в общие блоки.

Скомпилированные файлы (`*.css`, `*.css.map`, `*.min.css`, `*.min.js`) — артефакты сборки. Правится всегда исходник, артефакты руками не создаются и не редактируются.

## Один блок — один файл

Каждый самостоятельный BEM-блок получает свой файл в `<blocks-dir>`, имя файла совпадает с именем блока:

```text
.form          -> _form.scss
.article-card  -> _article-card.scss
.site-nav      -> _site-nav.scss
```

Стили блока не размещаются в `<scss-entry>`, в core-файлах и в файле другого блока.

## Структура файла

Первая строка — `<helpers-import>`, сразу за ней комментарий с именем блока:

```scss
<helpers-import>

/* article-card */

.article-card {
  ...
}
```

## Подключение

Файл блока подключается в `<blocks-index>` тем способом, который принят в проекте (`@forward`, `@use` или `@import` — см. слот):

```scss
@forward "form";
@forward "article-card";
@forward "site-nav";
```

Создать файл и забыть подключение — самая частая ошибка: стили просто не попадут в сборку. Напрямую в `<scss-entry>` блоки не подключаются.

## Preflight: сначала готовое

До написания первой строки стилей:

1. Открыть `<tokens-map>`, если он есть в проекте.
2. Открыть `<ui-dir>` и `<tokens-impl>`.
3. Проверить, есть ли готовый класс, миксин или семантический токен под типографику, цвет, фон, радиус, transition, кнопку, ссылку.
4. Только после этого писать локальные правила блока.

Что из этого следует:

- Типографику не набирать руками через `font-family`, `font-size`, `font-weight`, `line-height`, `letter-spacing`, если нужный стиль уже есть. Использовать `<typography-class>` в HTML или `<typography-mixin>` в SCSS по паттерну соседних блоков.
- Кнопки, ссылки и прочие примитивы не переопределять в файле блока, если они уже описаны в `<ui-dir>`.
- Цвета, фоны, радиусы и transition брать токенами `<token-*>`, а не raw-значениями из макета.

Raw-значения из макета допустимы только для локальной геометрии конкретного блока — `grid`, `gap`, `padding`, `min-height`, `aspect-ratio` — когда подходящего токена в проекте нет.

Если проект многотемный (слот `<themes>`), цвет, взятый raw-значением вместо семантического токена, ломает блок в одной из тем. Это не стилистическое замечание, а поломка.

## Вложенность

Элементы и модификаторы пишутся внутри родительского селектора через `&`:

```scss
.article-card {
  &--featured {
    ...
  }

  &__image {
    ...
  }

  &__button {
    ...

    &--disabled {
      ...
    }
  }
}
```

Неправильно — элементы отдельными корневыми селекторами:

```scss
.article-card { ... }
.article-card__image { ... }
```

## Адаптив

Медиа-запросы пишутся внутри того селектора, к которому относятся, и только миксинами проекта:

```scss
.article-card {
  display: grid;
  grid-template-columns: 120px 1fr;

  @include <media-sm> {
    grid-template-columns: 1fr;
  }

  &__title {
    @include <typography-mixin>;

    @include <media-xs> {
      @include <typography-mixin>;
    }
  }
}
```

Прямые `@media` в файлах блоков запрещены. Отдельный блок правил в конце файла вместо вложенного миксина — тоже.

## Hover

Только через `<hover-mixin>`:

```scss
.article-card {
  &__link {
    color: var(<token-text>);

    @include <hover-mixin> {
      color: var(<token-accent>);
    }
  }
}
```

Прямой `:hover` запрещён: миксин учитывает устройства без hover и добавляет `:active` для touch.

## Чеклист

- Стиль положен в правильное место: блок, page-only или шаблон компонента.
- Один блок — один файл, имя файла совпадает с именем блока.
- Первая строка — `<helpers-import>`, за ней комментарий с именем блока.
- Файл блока подключён в `<blocks-index>`.
- Перед стилями проверены `<tokens-map>`, `<ui-dir>` и `<tokens-impl>`.
- Типографика взята классами или миксинами, а не набрана свойствами.
- Цвета, фоны, радиусы и transition — семантическими токенами; raw-значения только под локальную геометрию.
- Элементы и модификаторы вложены через `&`.
- Адаптив — миксинами проекта, прямых `@media` нет.
- Hover — миксином проекта, прямого `:hover` нет.
- Скомпилированные артефакты не тронуты.
- В итоговом коде не осталось неподставленных `<слотов>`.
