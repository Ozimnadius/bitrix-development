# Перенос из Figma

Процедура переноса макета в шаблон. Заменяет собой отдельные MD-планы страниц и блоков: планы не создаются, работа идёт по этому файлу.

Разметка делается по `html.md`, стили — по `scss.md`. Здесь только порядок работы и что именно переносится.

Имена в угловых скобках — слоты `PROJECT.md`. В код они не попадают: сначала подставляется значение из контракта, и если слот пуст — сначала бутстрап.

## Данные из Figma

- metadata или структура страницы — чтобы определить крупные зоны;
- context конкретного node — чтобы сгенерировать внутренний блок и перенести контент;
- переменные и ассеты — по мере необходимости.

Технический код из Figma context (React, Tailwind, инлайн-стили) напрямую не переносится: он адаптируется к BEM и токенам проекта.

## Три режима

Режим выбирает пользователь через мастер вопросов в `SKILL.md`. Если он не указан и не очевиден из постановки — спросить, а не выбирать самому.

### Режим 1. Скелет страницы

Разложить страницу на крупные зоны без детализации.

1. Получить структуру страницы из Figma.
2. Определить верхний BEM-блок страницы, например `main`.
3. Определить крупные зоны и оформить их элементами верхнего блока.
4. Создать файл стилей страницы только со скелетом элементов.
5. Подключить его в индексе блоков.

```html
<main class="main">
  <div class="main__hero"></div>
  <div class="main__about"></div>
  <div class="main__contacts"></div>
</main>
```

```scss
<helpers-import>

/* main */

.main {
  &__hero {
  }

  &__about {
  }

  &__contacts {
  }
}
```

В этом режиме не создавать внутренние блоки, не переносить содержимое секций, не описывать финальные CSS-свойства.

### Режим 2. Скелет + внутренние блоки

Сразу наполнить зоны самостоятельными блоками с контентом.

1. Сделать верхний скелет как в режиме 1.
2. Для каждой крупной зоны получить context её node.
3. Внутри зоны создать самостоятельный блок: в `main__hero` — `main-hero`, в `main__about` — `main-about`.
4. Перенести в HTML реальный контент.
5. Для каждого внутреннего блока создать свой файл стилей со скелетом.
6. Подключить новые файлы в индексе блоков.

Внутренний блок не может остаться пустой заглушкой: его HTML отражает структуру и содержимое своей ноды.

### Режим 3. Внутренний блок в готовом скелете

Скелет уже есть, нужен один блок внутри готовой зоны.

1. Открыть текущий HTML страницы.
2. Найти родительскую зону и убедиться, что она соответствует нужной ноде. Когда зона очевидна из имени блока — `main-hero` живёт внутри `main__hero`, `main-about` внутри `main__about` — не спрашивать её отдельно. Если очевидного соответствия нет или подходящих зон несколько, спросить.
3. Получить context ноды.
4. Добавить или использовать контейнер, если дизайн ограничен по ширине.
5. Создать внутри самостоятельный блок и перенести контент.
6. Создать или дополнить файл стилей блока, подключить в индексе, если ещё не подключён.

Нельзя: пересоздавать верхний блок страницы, менять порядок и имена существующих зон без согласования, трогать соседние зоны, оставлять блок пустым.

```html
<main class="main">
  <div class="main__hero">
    <div class="<container>">
      <section class="main-hero">
        <div class="main-hero__container">
          <h1 class="main-hero__title">Заголовок из макета</h1>
        </div>
      </section>
    </div>
  </div>
</main>
```

## Что переносим

- реальные заголовки и тексты;
- подписи кнопок и ссылок;
- карточки и повторяющиеся элементы — со структурой повтора и содержимым видимых карточек;
- табы, бейджи, навигацию;
- изображения, иконки и SVG — ассетами или placeholder'ами с привязкой к node;
- порядок элементов как в макете.

Заменять доступный текст на `...` нельзя. Выдумывать то, чего в макете нет, тоже.

## Что не переносим

Если задача про структуру:

- финальные CSS-свойства и pixel-perfect размеры;
- JS-поведение;
- подключение компонентов и динамические данные.

Стили в этом случае остаются скелетными; свойства, адаптив и hover — отдельной задачей.

## Изображения

Режим `picture` или `img` выбирается до генерации HTML, разметка — по разделу «Изображения» в `html.md`.

При `picture` запросить у пользователя Figma-ссылки на версии для других разрешений и получить context по каждой. Не дали — использовать только доступный источник, а не выдумывать адаптивные варианты.

## Типы блоков

Если блок относится к известному типу, дополнительно читается его файл из `references/block-types/`. Спецификация типа не отменяет общие правила BEM и стилей, а дополняет их.

Сейчас описан один тип: слайдеры, карусели, блоки с pagination, точками или стрелками — `block-types/slider.md`.

## Чеклист

- Режим выбран явно.
- `html.md` и `scss.md` учтены, их чеклисты пройдены.
- Верхний блок страницы и её зоны оформлены корректно.
- В режимах 2 и 3 внутренние блоки самостоятельные и содержат реальный контент.
- В режиме 3 соседние зоны не изменены.
- Тексты из макета перенесены, не заменены многоточиями, ничего не выдумано.
- Для изображений выбран режим; при `picture` использованы только предоставленные ноды.
- Если блок типовой — его спецификация учтена.
- Отдельные MD-планы страниц и блоков не созданы.
