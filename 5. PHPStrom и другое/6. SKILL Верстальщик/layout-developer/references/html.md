# HTML-структура

Правила разметки: каркас страницы, контейнеры, BEM, выбор семантического тега, изображения.

Имена в угловых скобках — слоты `PROJECT.md`. В готовую разметку они не попадают: сначала подставляется значение из контракта, и если слот пуст — сначала бутстрап.

## Каркас страницы

Страница строится вокруг общего layout-контейнера `<page-wrapper>`:

```html
<body>
  <div class="<page-wrapper>">
    <div class="<page-wrapper>__panel"><!-- панель админки --></div>
    <div class="<page-wrapper>__header"><!-- шапка сайта --></div>
    <div class="<page-wrapper>__content"><!-- содержимое страницы --></div>
    <div class="<page-wrapper>__footer"><!-- подвал сайта --></div>
  </div>
</body>
```

Каркас задаётся шаблоном сайта, а не страницей. Менять его, шапку или подвал ради конкретной страницы нельзя — только по отдельному согласованию.

## Контейнеры

Ширину контента ограничивает существующий класс `<container>`.

- Использовать готовый класс проекта, а не заводить `page-container`, `content-container`, `main-container`.
- Не вкладывать контейнер в контейнер.
- Если блоку нужна собственная раскладка — это элемент блока, например `article-card__container`, а не второй контейнер.

Порядок вложенности для внутреннего блока страницы:

1. зона верхнего блока страницы — `main__hero`;
2. `<container>`;
3. самостоятельный BEM-блок — `main-hero`;
4. элементы блока — `main-hero__container`.

Правильно:

```html
<div class="main__hero">
  <div class="<container>">
    <section class="main-hero">
      <div class="main-hero__container">
        ...
      </div>
    </section>
  </div>
</div>
```

Неправильно — контейнер утоплен внутрь блока:

```html
<div class="main__hero">
  <section class="main-hero">
    <div class="<container>">
      ...
    </div>
  </section>
</div>
```

Если дизайн показывает ограниченную по ширине полосу контента, контейнер обязателен. Full-width допустим, только когда макет явно показывает блок во всю ширину экрана.

## BEM

```html
<div class="article-card">
  <div class="article-card__image"></div>
  <div class="article-card__body"></div>
  <a class="article-card__link article-card__link--active" href="#">…</a>
</div>
```

- Элемент `block__element` живёт только внутри своего блока.
- Модификатор не существует без базового класса.
- Самостоятельный смысловой фрагмент — это новый блок, а не элемент чужого блока.
- Имена короткие и смысловые. Длинное составное имя оправдано, только если короткое теряет смысл.
- Имя описывает назначение, а не внешний вид: `services-section`, `article-card`, `site-nav` — да; `gray-section`, `large-box`, `left-column` — нет.

Неправильно — элемент чужого блока внутри карточки:

```html
<div class="article-card">
  <div class="header__user-menu">…</div>
</div>
```

## Выбор тега

Тег выбирается по смыслу, а не по привычке. `<section>` не ставится автоматически на каждый новый блок.

| Тег | Когда |
|---|---|
| `section` | тематическая секция с самостоятельным смыслом |
| `nav` | навигационный блок |
| `header` / `footer` | шапка и подвал страницы или крупного самостоятельного блока |
| `main` | основное содержимое, если его не задаёт шаблон сайта |
| `aside` | боковая или вспомогательная область |
| `article` | самостоятельная карточка материала, новости, записи |
| `div` | нейтральная обёртка, когда семантического тега нет |

Порядок действий: выбрать тег по смыслу → назначить внешнему узлу BEM-блок → добавить контейнер, если нужна ограниченная ширина → добавить элемент блока для внутренней раскладки, если он нужен.

## Изображения

Два режима, выбор всегда явный — см. мастер вопросов в `SKILL.md`. Молча выбирать режим нельзя.

### picture

Когда для разных разрешений есть отдельные ноды макета, ассеты или явно разные версии изображения.

```html
<picture class="article-card__picture">
  <source media="(max-width: 767px)" srcset="path/to/image-mobile.webp">
  <source media="(max-width: 1199px)" srcset="path/to/image-tablet.webp">
  <img class="article-card__image" src="path/to/image-desktop.webp" alt="Описание изображения" loading="lazy">
</picture>
```

- BEM-класс ставится на `picture`, если обёртке нужен свой элемент блока.
- У fallback-`img` класс обязателен всегда.
- `source` — для альтернативных разрешений или форматов.
- Брейкпоинты в `media` берутся из тех же значений, что и миксины адаптива проекта, а не назначаются произвольно.
- Если ссылок на адаптивные ноды не дали — не выдумывать дополнительные изображения.

### img

Когда изображение одно.

```html
<img class="article-card__image" src="path/to/image.webp" alt="Описание изображения" loading="lazy">
```

Не подменять выбранный `img` на `picture` без согласования.

### Общее для обоих режимов

- `loading="lazy"` — на каждый новый `img`.
- `alt` осмысленный; для декоративного изображения допустим пустой `alt=""`.
- Нет ассета — понятный placeholder с привязкой к ноде макета, а не выдуманный путь.

## Чеклист

- Каркас страницы не тронут.
- Тег выбран по семантике.
- Контейнер использован там, где дизайн ограничен по ширине; контейнер в контейнере отсутствует.
- Для внутреннего блока соблюдён порядок `page__zone > <container> > block`.
- Новый смысловой фрагмент оформлен самостоятельным BEM-блоком.
- Элементы чужих блоков не смешаны в одной структуре.
- Имена блоков смысловые, не по внешнему виду, и не раздуты.
- Для изображений выбран режим, у каждого `img` есть класс, `alt` и `loading="lazy"`.
- Нет inline-стилей.
- Нет лишних обёрток, не нужных ни семантике, ни сетке, ни состоянию, ни JS.
- Нет временной демо-разметки в качестве целевой структуры.
- В итоговой разметке не осталось неподставленных `<слотов>`.
